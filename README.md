# 总决赛心得

> 由于总决赛只有一天时间，所有我们没有整一些特别的花活。借鉴了我们团队在省赛[raicom-2026-zhihai-provincial-second-prize](https://github.com/king-66jack/raicom-2026-zhihai-provincial-second-prize)的经验

本次任务是25类交通图像分类，相比省赛而言，本次类别更多，图片尺寸更小，数据量还是大差不差的。

## 结果

该方案在平台的验证集中取得的分数：**0.9646**。

## 数据处理

抽样检查了一遍数据，没有发现明显的标签错误；但老问题还在——**类别不均衡**。

时间所限，我们没有尝试外部数据扩充。事后看这事也没那么容易：官方没说明交通标志来自哪些国家，

我们对照了该领域知名的 ***\*GTSRB\****（German Traffic Sign Recognition Benchmark，德国、43 类，

本身也是类别不均衡的）等数据集，发现组委会把国外和国内的标志混在了一起（这是后话）。

真要扩充，得同时覆盖 GTSRB、清华-腾讯 ***\*TT100K\****（221 类，本身就包含大量光照/天气变化）

这类多源数据，还要解决类别体系对不齐的问题——一天时间根本不够。

## 数据增强

赛题强调复杂恶劣天气（雨雪、雾霾、沙尘）情况下的图像。该类情况下，图像比较灰蒙蒙的，对比度很低，感觉全部胡在一块。所以我们的应对分两路走：**一路"造脏"**，用天气模拟把这种灰蒙、低对比度的成像条件在训练集里复现出来，让模型提前习惯；**一路"提亮"**，用 CLAHE 这类局部对比度增强把灰图里本来就存在的微弱边缘重新拉出来。两路必须配合——只造脏不提亮，模型在极端退化下没东西可看；只提亮不造脏，模型一到真实雨雾又不会处理。最后提一嘴，在图像上挖块也是一个不错的手段，强迫模型只依据局部信息就做出判断而忽略其他有用的特征。

有一个库可以帮助我们完成这个任务---**Albumentations**

## 预训练模型选型

Top 1: ConvNeXt V2 (尺寸: tiny)

Top 2: EVA-02 (Base )

Top 3: MaxViT V2 ( Base)

Top 4: Swin Transformer V2 (Base )

相比省赛，我们增加了MaxViT V2这个模型。他的特点在于：它巧妙地结合了 CNN 的局部感知（抗模糊）和 Transformer 的全局注意力（抗遮挡）。我们查看了一些博客和一些综述文件，他们都强调这个模型在通用图像分析能力之强（吸取省赛的教训去看看有什么SOTA的预训练模型）

## train策略

时间紧，不可能拍脑袋定超参，更没算力做网格搜索。我的做法：**读原论文的实验设置 + 社区反馈，

把搜索空间压到最小**。这一步现在挺简单——把论文丢给 AI，让它把训练配方提炼成一张表，

来回聊个七七八八，心里自然就有"信念"了。



通用起手式（具体以各论文为准）：AdamW + cosine 衰减 + 短 warmup；ViT 系加 layer-wise lr decay；

label smoothing 0.1；AMP 混合精度省算力；有条件再上 EMA。精力只花在 lr 和 epoch 上，其余抄默认。

另外图片本来就小，输入分辨率别盲目拉大，224 往往就够，384/512 烧算力但收益未必明显。

## 心得

总结来说，在本届比赛中，想得奖很大取决于你拥有多少算力，代码可以AI写，只要做好决策就行（我也尝试让AI做个决策，虽然比较详细，但是太面面俱到了，你根本没有那么充足的时间，同样我认为AI的品味不是很好，有些方法一看就有点老掉牙了）。

最后说一个小插曲，其实我想给自己出一个题目，尝试的在一个参数量小的模型（ConvNeXt V2  tiny ， 选择他的原因是他作为基模在很多的下游任务中有大量应用，在此方面有大量的论文，可以给我指导）上做到极致，也就是尝试对模型的架构进行改变，比如尝试多叠网络结果，修改loss函数，替换分类头（线性分类头或者MLP头）。最后的结果才只有**0.9498**，在这场比赛中没有没有很大的竞争力，随不了了之。而转向力大砖飞。
